# Feature Specification: 와이어프레임 코치 스위트

## Overview

디자인캠프 산출물 md 5종을 입력으로 받는 대화형 코치 스킬 2개.

- 입력 파일 5종 (Workshop Agent 1~4 산출물):
  1. 업무 Task Tree 정의서 (Agent 1)
  2. Task Tree 정의서 통합본 (Agent 2-1)
  3. PP·AX 매핑 정의서 (Agent 2-2)
  4. Process Flow 설계서 (Agent 3)
  5. To-Be 종합보고서 (Agent 4)
- 파일이 5종 미만이어도 동작한다. 없는 정보는 `(미정)` 또는 대화로 보충한다.

## User Scenarios & Testing (mandatory)

### User Story 1: Lv5 선정 (모더레이터 코치)

- As: 워크샵 팀(모더레이터 진행)은
- I: md 5종을 올려 전체 Lv4 프로세스 지도와 Lv5 후보 워크시트를 받고, 후보 하나의 에이전트 적절성 판정을 받을 수 있다
- So: 오후 제작 세션에서 만들 팀 에이전트 대상을 근거 있게 고르기 위해

#### Acceptance Scenarios

Scenario 1: **정상 흐름**
- Given md 5종 업로드
- When 코치가 파싱 완료
- Then ① 전체 Lv4 목록(빈도·PP·AX추천 표시) ② Lv5 후보 × 5기준 워크시트 HTML 1장 ③ 팀 선택 후 판정(권장/조건부 권장/대안 권장) + `@@STATE@@` 블록 출력

Scenario 2: **파일 부족**
- Given 파일 1~2종만 업로드
- When 워크시트 채움에 필요한 값이 없음
- Then 해당 칸을 `❓미확인`으로 두고 진행하며, 지어내지 않는다

Scenario 3: **대안 권장**
- Given 선택한 Lv5가 기준 다수 미충족
- When 판정 완료
- Then 워크시트에서 충족 수 상위 후보 2~3개를 다시 제시하고 재선택을 받는다 (세션을 빈손으로 끝내지 않는다)

### User Story 2: 와이어프레임 조정 + 스킬 추천 (와이어프레임 코치)

- As: 선정된 Lv5의 담당 참가자는
- I: 대화로 To-Be 와이어프레임을 조정하고, 노드별 방식(자동화/스킬/사람) 판정과 만들 스킬 2~3개 추천을 받을 수 있다
- So: 다음 제작 세션에서 바로 스킬을 만들기 위해

#### Acceptance Scenarios

Scenario 1: **상태 블록 이어받기**
- Given 스킬 1의 `@@STATE@@` 블록 붙여넣기
- When 코치 시작
- Then 이미 있는 정보(Lv5명, 판정, Lv6 목록)를 다시 묻지 않고 확인만 한다

Scenario 2: **판단기준 캐기**
- Given 처리 칸이 "검토한다" 등 한 단어
- When 코치가 3단(무엇을 보나 → 경계 → 애매 구간)으로 파고듦
- Then "만약 ~면 ~한다" 문장 2~3개가 노드 속성에 기록된다

Scenario 3: **스킬 추천**
- Given To-Be 트리 확정
- When 최종 출력
- Then 스킬 방식 노드를 묶어 **스킬 2~3개**를 이름+한 줄 정의+우선순위로 추천하고, HTML 시각화 + `@@STATE@@` 갱신 블록을 낸다

## Functional Requirements

- FR-1: 두 스킬 모두 md 파일 상단에 `name`/`description` 프론트매터를 갖는다. description에 발동 조건을 구체적으로 적는다.
- FR-2: 대화 원칙 — 한 턴에 질문 1개 / 빈칸으로 되묻지 않기(보기 2~3개) / 같은 질문 3회 금지.
- FR-3 (스킬 1): 워크시트 5기준 = ①반복성 ②위임 가능성 ③다단계성 ④순서 가변성 ⑤검증 가능성. md 파일에서 자동 채움(빈도, HITL 분포, Lv6 수, 분기·루프백, HITL 존재). ⑥가치(시간)는 판정 단계에서 대화로만 받는다.
- FR-4 (스킬 1): 판정 값은 권장/조건부 권장/대안 권장 3종. 게이트 값은 충족/미충족/미확인 3종. 점수·등급 금지.
- FR-5 (스킬 2): 트리는 `flowchart LR` 고정, 환경태그 5종(🧠 📥 📤 🚧 👤) + 아이콘 라벨 필수.
- FR-6 (스킬 2): 노드 방식 판정은 자동화/스킬/사람 3종. 스킬 추천은 2~3개, 각각 스킬명(동작 중심) + 인풋→아웃풋 한 줄 정의 + 우선순위 근거.
- FR-7: 두 스킬 모두 산출물 끝에 `@@STATE@@ ... @@END@@` 상태 블록을 내고, 시작 시 상태 블록을 받으면 5문항 리부트 체크로 복구한다.
- FR-8 (paperthin): 판정은 빼기가 기본 — 애매하면 더 단순한 방식으로. 코치는 판단·설계만 하고 스킬 본문/프롬프트/분해 재작업을 하지 않는다.

## Constraints

- CON-1: 사내 실데이터(수치·거래처·인사)는 되풀이 인용하지 않는다.
- CON-2: [추론] 태그가 붙은 값은 판정 근거로 쓸 때 "AI 추론값"임을 표기하고 참가자 확인을 받는다.
- CON-3: 레벨 명칭이 파일마다 다르므로(Agent 1: Lv5=Activity / Agent 3~4: Lv5=Task·Lv6=Activity) 코치는 시작 시 입력 파일의 레벨 정의 표를 읽어 그 파일의 명칭을 그대로 따른다.

## Success Criteria

- SC-1: md 5종 입력 → 15~20분 내 Lv5 선정·판정 완료 (스킬 1)
- SC-2: 선정 Lv5 → 20~25분 내 To-Be 트리 + 스킬 추천 2~3개 (스킬 2)
- SC-3: 세션 중단 후 상태 블록만으로 재개 가능
