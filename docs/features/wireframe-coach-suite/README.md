# 와이어프레임 코치 스위트 (모더레이터 코치 + 코치)

## Background

기존에 별도로 설계된 두 스킬이 있었다.

- **AgentTaskFit v3.0 (핏 코치)** — 분해된 업무를 놓고 에이전트 적합성을 6기준으로 판정
- **WireframeCoach v8** — 참가자 1명의 LV6 하나를 To-Be 와이어프레임으로 재설계

한편 디자인캠프(AI 전환 전략 워크샵)는 Workshop Agent 1~4가 md 파일 5종을 산출한다
(업무 트리 정의서 / 통합본 / Pain Point(업무상 불편·병목) 및 AI 전환 매핑 정의서 / 업무 흐름 설계서 / 개선안 종합보고서).
이 5종을 입력으로 받아 팀이 **어느 업무를 에이전트/스킬로 만들지** 고르고,
**어떻게 만들지** 와이어프레임으로 다듬는 흐름이 필요하다.

두 저장소의 철학을 채택한다.

- **file-based-planning-workflow**: 파일이 곧 기억이다. 판정·결정을 즉시 산출물에 기록하고,
  세션이 끊겨도 산출물(상태 블록)만 읽으면 이어서 진행할 수 있어야 한다.
- **paperthin**: 절제. 스킬 하나는 실패 모드 하나만 겨냥한다. 더하기보다 빼기 —
  후보를 늘리는 게 아니라 줄이는 것이 판정의 기본이고, 산출물은 얇게 유지한다.

## Goal

디자인캠프 md 5종을 받아 순서대로 쓰는 스킬 2개를 만든다.

1. **와이어프레임 모더레이터 코치** (`skills/wireframe-moderator-coach.md`)
   — 결과 읽기, 전체 지도, Lv4, Lv5, 현재 Lv5의 Lv6, 최종 토의로 나뉜 6페이지 HTML 선정 보드를 만든다.
   Lv4와 Lv5는 각각 페이지를 넘겨 비교하고, 사람 준비·시스템 연동·사람 최종 책임 업무는 화면에 보존하되 자동화 수에서는 제외한다.
   팀이 고른 Lv5의 에이전트 적절성을 판정한다. (겨냥하는 실패 모드: **잘못된 후보 선정**)
2. **와이어프레임 코치** (`skills/wireframe-coach.md`)
   — 대화로 To-Be 와이어프레임을 조정하고, 노드별 스킬 적절성을 판정하며,
   만들 스킬 2~3개를 추천한다. (겨냥하는 실패 모드: **뭉뚱그린 판단 기준**)

## How it works

### 스킬 1 → 스킬 2 연결 (파일이 기억)

- 스킬 1은 판정 결과를 6페이지 HTML 선정 보드 + 상태 블록(`@@STATE@@`)으로 남긴다.
- 스킬 2는 그 상태 블록(또는 md 5종)을 읽고 시작하며, 5문항 리부트 체크로 맥락을 복구한다.
- 확인 안 된 값은 지어내지 않고 `(미정)`으로 남긴다.
