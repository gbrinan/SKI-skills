# Findings & Decisions

## Research Findings

- 반복 사용 정보는 스킬 본문에 직접 넣기보다 별도 프로필 파일로 두어야 수정과 공유가 쉽다.
- 예시는 강력한 기본값이 될 수 있으므로 실제 조직명과 사실을 복사하지 못하도록 명시해야 한다.
- 현재 요청과 고객 요구가 프로필보다 우선해야 프로젝트별 요구와 충돌하지 않는다.

## Technical Decisions

| Decision | Rationale |
| --- | --- |
| 스킬 이름을 `build-corporate-training-decks`로 지정 | 특정 회사나 교육 브랜드에 종속되지 않는다 |
| 프로필을 `references/user-profile.md`에 분리 | 사용자가 한 곳만 편집해 반복 사용 가능하다 |
| 프로필은 빈칸과 안전한 기본값으로 제공 | 개인 정보를 추측하거나 예시 인물을 실제 정보로 오인하지 않는다 |
| 현재 요청을 최우선으로 적용 | 프로젝트별 요구가 영구 프로필에 막히지 않는다 |
| 상세 기준과 예시를 참조 파일로 분리 | 핵심 `SKILL.md`를 단순하게 유지한다 |

## Issues Encountered

- 원래 작업 폴더는 상위 사용자 홈 저장소에 속했고 원격이 없었다. GitHub 계정의 `SKI-skills` 저장소와 같은 로컬 저장소를 확인해, 기존 미추적 작업을 보존하는 별도 worktree에서 진행했다.
- 공식 검증기가 Windows 기본 CP949로 UTF-8 한글을 읽지 못했다. 파일을 변경하지 않고 Python `-X utf8` 모드로 재실행해 통과했다.

## Counterpoint

프로필을 YAML 파일로 두면 채팅에서 즉시 입력하는 방식보다 진입 장벽이 있다. 그러나 반복 사용, 변경 추적, 우선순위 검증이 더 명확하므로 현재 구조를 유지하고 필드 설명과 완성 예시를 함께 제공한다.
